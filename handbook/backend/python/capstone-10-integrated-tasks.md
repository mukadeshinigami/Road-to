# 10 интегративных задач (все 7 блоков)

После прохождения уроков `01`–`07` эти задания **собирают темы в одном проекте**. У каждой задачи указано, какие блоки она затрагивает (цифры **1**–**7**).

**Общие ожидания (для каждой из 10 задач):**

- **1** — `venv`, entry point с `if __name__ == "__main__"`, коллекции / f-strings там, где уместно
- **2** — разнесение по модулям, `argparse` (или субкоманды), осмысленные функции без «магии»
- **3** — хотя бы один класс или `@dataclass`, при необходимости контекстный менеджер
- **4** — `pathlib`, свои исключения, `try`/`except` без голого `except:`
- **5** — аннотации публичного API, `mypy` или `pyright` без игноров «на весь файл»
- **6** — `pytest`, фикстура `tmp_path` или аналог, `pyproject.toml` (хотя бы для dev-deps)
- **7** — **обязательно** хоть один осмысленный фрагмент `asyncio`: например `asyncio.gather` двух корутин (валидация, «удалённые» проверки, параллельное чтение мелких файлов, `to_thread` для тяжёлого вызова) + `asyncio.run` в CLI или отдельной подкоманде

Так каждая задача закрепляет **все семь** блоков курса.

## Задача 1 — `repokit`: инвентарь репозитория

**Блоки:** 1–7  

CLI: `repokit scan <path>` — обойти дерево (`pathlib`), для каждого `.py` собрать: размер, число строк (приблизительно), хэш SHA-256 (можно `hashlib` в `asyncio.to_thread` для крупных файлов). Вывод: JSON в stdout или файл (`--out`). Ошибки доступа к файлу — логировать и продолжать. Типы для конфигурации запуска (`TypedDict` или `dataclass`). Тесты на временной дереве из фикстуры. **Async:** `asyncio.gather` для параллельного хэширования (или другого тяжёлого шага) для списка файлов с `Semaphore` на ограничение конкуренции.

## Задача 2 — слой конфигурации для приложения

**Блоки:** 1–7  

Файл `app.toml` или `app.json` в `Path`, загрузка + merge с defaults. Свои ошибки: `ConfigMissing`, `ConfigInvalid`. Модуль `config.py` + `main.py`. Полная типизация загрузчика. Pytest: невалидный JSON, отсутствующий файл, успешный merge. **Async:** подкоманда `verify` запускает `asyncio.gather` двух корутин «проверки» (например `asyncio.sleep` + проверка обязательных ключей в разных поддеревьях конфига) и объединяет результат в общий отчёт.

## Задача 3 — мини «генератор заметок» (Markdown → HTML)

**Блоки:** 1–7  

Папка с `.md`: для каждого файла сгенерировать `.html` в `dist/` (шаблон — простая строка или `string.Template`). Класс `Builder` с методами, контекстный менеджер для «сессии сборки» (тайминг или лог). Атомарная запись каждого HTML. `asyncio` — параллельное чтение исходников с диска. CLI с флагами `--src`, `--out`. Тесты на двух файлах во `tmp_path`.

---

## Задача 4 — очередь задач с персистентностью

**Блоки:** 1–7  

`@dataclass` задача: `id`, `payload: dict`, статус. Хранение в JSONL (`pathlib`). API: добавить задачу, взять следующую, отметить выполненной. `Protocol` для «исполнителя» (sync). Async-воркер: несколько корутин забирают задачи из очереди `asyncio.Queue`, исполняют через `to_thread` вызов sync-исполнителя. CLI: `enqueue`, `worker`. Pytest на состоянии файла после сбоев (имитация).

---

## Задача 5 — слияние и статистика логов

**Блоки:** 1–7  

Несколько `.log` файлов: параллельно (`asyncio`) прочитать, слить по времени (упрости: по строкам с префиксом timestamp или просто concat + sort). Статистика: топ-N строк по частоте (`Counter`). Свои исключения при битой кодировке. CLI. Типизированные структуры для отчёта. Pytest на золотом эталоне вывода.

---

## Задача 6 — хост плагинов (Protocol)

**Блоки:** 1–7  

`Protocol` `Plugin` с методом `run(data: str) -> str`. Реестр: имя → фабрика или импорт по строке пути (`importlib`). CLI: `run --plugin foo --input bar`. Обработка ошибок плагина. **Async:** параллельная «инициализация» нескольких плагинов через `asyncio.gather` (имитация I/O `sleep`) перед запуском выбранного. Тесты с фейковым плагином во `tmp_path` (динамический `.py`).

---

## Задача 7 — зеркалирование URL в каталог

**Блоки:** 1–7  

Список URL (файл или аргументы): **асинхронно** скачать (лучше `httpx` async или `aiohttp`; если не хочешь зависимости — `urllib` в `to_thread` с ограничением семафора). Имена файлов из URL-safe путей, каталог назначения через `pathlib`. Таймаут, ретраи не обязательны. Типы, CLI, pytest с `pytest-httpserver` или mock transport.

---

## Задача 8 — pipeline: CSV → нормализованный JSON + отчёт

**Блоки:** 1–7  

Модуль `csv` из stdlib. Классы стадий: `Reader`, `Transformer`, `Writer` (композиция). Ошибки валидации строк — собирать в список, в конце exit code ≠ 0 при любых ошибках. `TypedDict` для строки выхода. Pytest на фикстурном CSV. **Async:** параллельное чтение двух входных CSV через `asyncio.gather` + `asyncio.to_thread` обёртку над синхронным чтением (если один файл — разбей на два чанка/два пути для учебной цели).

## Задача 9 — безопасное обновление секрета в файле

**Блоки:** 1–7  

Файл `.env`-подобный: `KEY=value`. CLI: `set-secret KEY` (читает value из stdin или `KEY=value`). Бэкап старого файла с timestamp, атомарная запись нового. Контекстный менеджер «откат при ошибке». Тесты на `tmp_path`, проверка бэкапа. **Async:** после успешной записи `asyncio.gather` двух корутин «уведомления» (например `sleep` + логирование в два канала-заглушки), чтобы отработать конкурентное завершение side-effects.

CLI `python -m textstats` с подкомандами `file`, `dir` (для `dir` — **async** обход и параллельное чтение с семафором). `pyproject.toml`, `ruff`, `pytest`, `mypy` на `src/`.

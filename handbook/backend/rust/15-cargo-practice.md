# Блок 15: Практика — Cargo и зависимости (Cargo & Dependencies)

## Цель практики

Добавить внешние зависимости, настроить features, собрать релиз и сгенерировать документацию.

---

## Задание 1: Проект с внешними зависимостями (serde, reqwest)

### Описание

Создать проект, в котором использовать `serde` (и `serde_json`) для сериализации структуры в JSON и при желании `reqwest` для одного HTTP GET (например, к jsonplaceholder.typicode.com). Добавить зависимости в Cargo.toml, собрать и запустить.

### Требования

- В Cargo.toml: `serde = { version = "1", features = ["derive"] }`, `serde_json = "1"`. При использовании HTTP: `reqwest = { version = "0.11", features = ["json"] }` (для блокирующего клиента может понадобиться feature "blocking").
- Структура с `#[derive(Serialize, Deserialize)]`, сериализация в строку через `serde_json::to_string`, вывод в консоль.
- Для reqwest: в main (или отдельной функции) выполнить GET, распарсить JSON в структуру и вывести (или просто текст ответа).

### Пример

```toml
[dependencies]
serde = { version = "1", features = ["derive"] }
serde_json = "1"
```

```rust
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize)]
struct User { name: String, id: u32 }

fn main() {
    let u = User { name: "Alice".into(), id: 1 };
    let s = serde_json::to_string(&u).unwrap();
    println!("{}", s);
}
```

Реализуйте и проверьте вывод.

## Задание 2: Настройка features

### Описание

В своём крейте объявить опциональную фичу `json` (или `network`). Если фича включена — компилировать модуль/функцию с сериализацией в JSON (или с запросом); если выключена — заглушка или только базовая логика. В Cargo.toml добавить `[features]` и в коде использовать `#[cfg(feature = "json")]`.

### Требования

- В Cargo.toml: `[features] default = [] json = ["serde", "serde_json"]` (и добавить serde только при feature в dependencies: `serde = { version = "1", optional = true }`).
- В коде: условная компиляция по `#[cfg(feature = "json")]` и вызов соответствующей логики в main.

Соберите с `cargo build` и с `cargo build --features json` и убедитесь, что поведение различается (или что с фичей код компилируется и выполняется).

## Задание 3: Оптимизация размера бинарника (релиз)

### Описание

Собрать проект в release и посмотреть размер бинарника. Добавить в Cargo.toml профиль с уменьшением размера: `opt-level = "z"` (или `"s"`), `lto = true`, `strip = true`. Сравнить размер до и после.

### Требования

- В [profile.release]: `opt-level = "z"` (или "s"), `lto = true`, при наличии компилятора/опций — `strip = true`.
- Выполнить `cargo build --release`, посмотреть размер файла в `target/release/`.

Кратко опишите, что дало наибольшее уменьшение (по возможности).

## Задание 4: Документирование крейта

### Описание

В библиотечном крейте (или в модуле с публичными функциями) добавить doc-комментарии к одной структуре и одной функции: краткое описание, пример использования в блоке кода (doc test). Сгенерировать документацию и открыть в браузере.

### Требования

- `/// Summary.` и при необходимости `/// # Examples` с блоком кода.
- Запуск `cargo doc --open`, проверка, что пример отображается и что doc test проходит при `cargo test`.

Пример:

```rust
/// Adds two numbers.
///
/// # Examples
/// ```
/// use my_crate::add;
/// assert_eq!(add(2, 3), 5);
/// ```
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

Реализуйте для своей функции/структуры.

# Блок 23: Unsafe Rust

## Цель

Понять, **когда и как** использовать **unsafe**: блоки и функции, сырые указатели, вызов unsafe-кода, FFI, связывание с C, правила безопасности и bindgen.

---

## 1. unsafe блоки и функции

Ключевое слово **unsafe** разблокирует возможности, которые компилятор не проверяет сам: разыменование сырых указателей, вызов unsafe-функций, доступ к изменяемой статики, реализация unsafe-трейтов. Код внутри блока по-прежнему должен соблюдать гарантии безопасности; ответственность на программисте.

```rust
unsafe {
    let p: *const i32 = ...;
    *p  // только внутри unsafe
}
```

Функция объявляется `unsafe fn`; вызывать её можно только из unsafe-блока или другой unsafe-функции.

---

## 2. Сырые указатели: *const T, *mut T

Сырые указатели не несут владения и времени жизни; их можно создавать в safe-коде, но разыменовывать — только в unsafe. Используются для FFI, низкоуровневых структур данных, оптимизаций с известными инвариантами.

```rust
let x = 5;
let p: *const i32 = &x;
unsafe { println!("{}", *p); }
```

---

## 3. Разыменование и вызов unsafe

Разыменование: `*raw_pointer`. Вызов: `unsafe { foreign_ffi_function(args) };`. Необходимо гарантировать: указатель валиден, выровнен, не используется после освобождения; при FFI — соответствие контракту C.

---

## 4. FFI (Foreign Function Interface)

Связывание с C: объявление внешних функций и типов через `extern "C"`:

```rust
#[link(name = "mylib")]
extern "C" {
    fn c_function(x: i32) -> i32;
}

fn main() {
    let r = unsafe { c_function(42) };
}
```

Передача строк, структур, колбэков требует соблюдения ABI и владения (например, CString для строк в C).

---

## 5. Связывание с C-библиотеками

В Cargo.toml можно указать системную библиотеку (например, через build.rs и cc/link). Крейт **bindgen** генерирует Rust-обёртки по C-заголовкам, уменьшая ручную работу и ошибки.

---

## 6. Правила безопасности в unsafe

Даже в unsafe нельзя нарушать: нет use-after-free, нет data races, нет невалидных значений. Unsafe лишь отключает часть проверок компилятора; инварианты должны быть задокументированы и обеспечены в коде. Рекомендуется минимизировать объём unsafe и изолировать его в небольших модулях с чётким контрактом.

---

## 7. Итоги

- unsafe разблокирует сырые указатели, вызов unsafe-функций, статику, unsafe-трейты.
- Сырые указатели *const T / *mut T; разыменование только в unsafe.
- FFI через extern "C"; bindgen для генерации биндингов.
- Безопасность — ответственность программиста; документировать инварианты.

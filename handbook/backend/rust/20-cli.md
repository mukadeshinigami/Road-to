# Блок 20: CLI приложения (Command-Line Applications)

## Цель

Создавать **профессиональные CLI-инструменты**: парсинг аргументов (clap), подкоманды, stdin/stdout, цветной вывод, progress bars, конфиг, обработка сигналов (Ctrl+C), кросс-платформенность.

---

## 1. clap для парсинга аргументов

Крейт **clap** — декларативный или программный парсинг флагов и позиционных аргументов. Версия 4.x: derive-макрос для структур.

```toml
[dependencies]
clap = { version = "4", features = ["derive"] }
```

```rust
use clap::Parser;

#[derive(Parser)]
#[command(name = "myapp")]
struct Args {
    #[arg(short, long)]
    config: Option<String>,
    #[arg(default_value = "0")]
    count: u32,
}

fn main() {
    let args = Args::parse();
    println!("{:?}", args.config);
}
```

Долгие и короткие флаги, значения по умолчанию, справка (--help) генерируются автоматически.

---

## 2. Subcommands

Подкоманды (как в git: clone, push):

```rust
#[derive(Parser)]
enum Cli {
    Add { name: String },
    List,
    Run { id: u32 },
}

fn main() {
    match Cli::parse() {
        Cli::Add { name } => { ... }
        Cli::List => { ... }
        Cli::Run { id } => { ... }
    }
}
```

## 3. stdin/stdout

Чтение из stdin: `std::io::stdin().lock()`, `BufRead::lines()`. Запись в stdout: `println!`, `print!`, либо `std::io::stdout()`. Для бинарных данных — `std::io::Read`/`Write`. Редиректы обрабатывает ОС; программа просто читает stdin и пишет в stdout.

---

## 4. Цветной вывод: colored, owo-colors

Крейты **colored** или **owo-colors** позволяют выводить цветной текст в терминал (если поддерживается). Проверка TTY: выводить цвета только если stdout — терминал, иначе обычный текст (чтобы пайпы не засорялись кодами).

---

## 5. Progress bars: indicatif

Крейт **indicatif** — прогресс-бары, спиннеры. Удобно при длительных операциях (скачивание, обход файлов). Пример: создать ProgressBar, обновлять в цикле, завершить по окончании.

---

## 6. Конфигурационные файлы

Конфиг в формате TOML/YAML/JSON: чтение файла (std::fs или tokio::fs), парсинг в структуру (serde). Переменные окружения — через std::env::var или крейт dotenvy. Приоритет: аргументы CLI > env > конфиг-файл (по договорённости).

---

## 7. Обработка сигналов (Ctrl+C)

В синхронном коде: крейт **ctrlc** или **signal-hook** для регистрации обработчика SIGINT; установить флаг или канал и корректно завершить цикл. В async: tokio::signal::ctrl_c().await и отмена задач/закрытие ресурсов.

---

## 8. Кросс-платформенность

Пути — через std::path::Path. Разделители и переменные окружения различаются (Windows vs Unix); по возможности использовать стандартную библиотеку и проверять на обеих платформах. Избегать shell-специфичного кода.

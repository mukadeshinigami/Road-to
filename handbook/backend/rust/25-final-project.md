# Блок 25: Финальный проект (Final Project)

## Цель

Собрать **всё воедино** в одном приложении: модульная структура, тесты, обработка ошибок, async при необходимости, документация, опционально CI/CD и деплой.

---

## Варианты проекта

1. **REST API сервис** — аутентификация (JWT или сессии), база данных (SQLite/PostgreSQL), CRUD, unit и integration тесты, документация API.
2. **CLI-инструмент** — парсинг аргументов (clap), чтение/запись файлов или сетевые запросы, вывод в консоль; тесты для ключевой логики.
3. **Веб-скрапер** — асинхронные HTTP-запросы, парсинг HTML (например, scraper), сохранение в БД или файлы; конкурентность через tokio.
4. **Чат-сервер** — TCP или WebSockets, несколько клиентов, broadcast сообщений, опционально Redis для очередей или истории.
5. **Игровой/прикладной сервер** — состояние игроков/сессий, обновление по событиям, персистентность.
6. **Компилятор/интерпретатор** — парсер простого языка, AST, выполнение или генерация кода; хорошая практика для структур данных и тестов.

---

## Общие требования

- **Модульная структура** — разбиение на крейты или модули (handlers, db, config, errors).
- **Тесты** — unit для бизнес-логики, integration для API или CLI.
- **Обработка ошибок** — свой тип ошибок или Box<dyn Error>, использование ? и логирование.
- **Async** — где уместно (сетевой I/O, БД); синхронный код — для простых CLI.
- **Документация** — README с запуском и примерами; doc-комментарии для публичного API; при API — описание эндпоинтов (OpenAPI по желанию).
- **CI/CD** — GitHub Actions (или аналог): сборка, тесты, clippy, fmt. Опционально — деплой (Docker, бинарник в release).

---

## Рекомендуемый порядок

1. Выбрать вариант и набросать список сущностей и операций.
2. Инициализировать проект (cargo, при необходимости workspace).
3. Реализовать ядро (модели, БД или хранилище, базовые функции).
4. Добавить слой API или CLI, подключить конфиг и логирование.
5. Написать тесты и пройтись clippy/fmt.
6. Оформить README и при желании CI.

---

## Критерии готовности

- Проект собирается и тесты проходят.
- Ошибки обрабатываются явно, без паники в библиотечном коде.
- Код разбит на модули; публичный API документирован.
- README объясняет, как запустить и чем пользоваться.
- При наличии API или скрапера — есть хотя бы один сценарий использования (пример запроса или команды).

# Блок 11: Итераторы и замыкания (Closures)

## Цель

Писать **функциональный код**: замыкания (closures), итераторы, цепочки методов (map, filter, fold, collect), ленивость и создание своих итераторов.

---

## 1. Замыкания (closures)

Замыкание — анонимная функция, которая может захватывать переменные из окружающей области видимости. Синтаксис: `|args| body`.

```rust
let add_one = |x| x + 1;
let add = |a, b| a + b;
let multi = |x: i32| -> i32 { x * 2 };
```

Типы аргументов и возвращаемого значения часто выводятся. Замыкание может захватывать переменные по ссылке, по изменяемой ссылке или по владению (`move`).

### Захват: borrow, move

По умолчанию — заимствование. Ключевое слово `move` передаёт владение захваченным переменным в замыкание:

```rust
let v = vec![1, 2, 3];
let f = move || v.len();  // v перемещено в замыкание
// v больше недоступен здесь
```

Нужно для передачи замыкания в поток (`thread::spawn`) или в async-контекст.

---

## 2. Трейты Fn, FnMut, FnOnce

- **FnOnce** — вызывается один раз; может потреблять захваченные значения.
- **FnMut** — может вызываться много раз, захватывает по изменяемой ссылке.
- **Fn** — может вызываться много раз, захватывает по неизменяемой ссылке.

Принимать замыкание в функции: `impl Fn(i32) -> i32` или `impl FnMut()`. Хранить в структуре: поле типа универсального замыкания сложнее (размер неизвестен), часто используют `Box<dyn Fn(...)>`.

---

## 3. Итераторы: iter, iter_mut, into_iter

- **iter()** — ссылки `&T`, коллекция остаётся.
- **iter_mut()** — изменяемые ссылки `&mut T`.
- **into_iter()** — потребляет коллекцию, отдаёт владение элементами.

Итератор реализует трейт `Iterator` с методом `next() -> Option<Self::Item>`. Цикл `for x in v.iter()` вызывает `next()` до `None`.

---

## 4. Методы итераторов: map, filter, fold, collect

- **map(|x| ...)** — преобразование каждого элемента.
- **filter(|x| ...)** — оставить только элементы, для которых предикат true.
- **fold(init, |acc, x| ...)** — свёртка в одно значение (аккумулятор).
- **collect()** — собрать в коллекцию (Vec, HashMap и т.д.); тип часто задают: `let v: Vec<_> = iter.collect()`.

Пример:

```rust
let v = vec![1, 2, 3, 4];
let sum: i32 = v.iter().map(|x| x * 2).sum();
let evens: Vec<_> = v.into_iter().filter(|x| *x % 2 == 0).collect();
```

Другие полезные: `take(n)`, `skip(n)`, `enumerate()`, `zip`, `chain`, `filter_map`.

---

## 5. Ленивость (lazy evaluation)

Итераторы не выполняют работу до момента потребления (вызов `next`, или `collect`, `sum`, `for`). Цепочка `map(...).filter(...)` лишь строит новый итератор; вычисления идут по одному элементу при обходе.

---

## 6. Создание собственных итераторов

Реализовать трейт `Iterator` для своего типа:

```rust
struct Counter { count: u32 }

impl Iterator for Counter {
    type Item = u32;
    fn next(&mut self) -> Option<Self::Item> {
        if self.count < 5 {
            self.count += 1;
            Some(self.count)
        } else {
            None
        }
    }
}
```

Тогда можно использовать `Counter::default()` (или с заданным началом) в цепочках с `map`, `filter`, `collect` и т.д.

---

## 7. Типичные ошибки

- Захват по ссылке в замыкании, которое переживает владельца — ошибка времени жизни; часто решается `move`.
- Вызов `next()` на consumed итераторе — он уже исчерпан; для повторного обхода нужна новая итерация (например, снова `iter()`).
- Путать `iter()` (ссылки) и `into_iter()` (владение) — от этого зависит, останется ли коллекция доступной после цикла.

---

## 8. Best practices

- Предпочитать итераторы и замыкания вместо ручных циклов, когда это читаемо (идоматичный Rust).
- Для сложной логики или отладки допустимы явные циклы.
- Создавать свой итератор, когда нужна повторно используемая логика обхода.

---

## 9. Итоги

- Замыкания: `|args| body`, захват по ссылке или `move`; FnOnce / FnMut / Fn.
- Итераторы: iter/iter_mut/into_iter; map, filter, fold, collect; ленивость.
- Свой итератор — реализация трейта `Iterator` с `next()`.

# Блок 8: Дженерики (Generics)

## Цель

Писать **переиспользуемый код** для разных типов без дублирования: дженерик функции, структуры, методы, ограничения типов (trait bounds) и клауза `where`.

---

## 1. Зачем нужны дженерики

Один и тот же алгоритм часто применим к разным типам (числа, точки, строки). Дженерики позволяют описать функцию или тип **один раз**, а компилятор подставит конкретные типы при компиляции (monomorphization) — без накладных расходов в рантайме.

---

## 2. Дженерик функции

Параметр типа указывается в угловых скобках после имени функции:

```rust
fn largest<T>(list: &[T]) -> &T
where
    T: PartialOrd,
{
    let mut largest = &list[0];
    for item in list.iter() {
        if item > largest {
            largest = item;
        }
    }
    largest
}
```

Без ограничения `T: PartialOrd` сравнение `item > largest` было бы невозможно — компилятор не знает, что для `T` определено сравнение. Ограничения задаются через **trait bounds**: `T: PartialOrd` или в сигнатуре: `fn largest<T: PartialOrd>(list: &[T]) -> &T`.

### Множественные параметры типов

```rust
fn pair<T, U>(a: T, b: U) -> (T, U) {
    (a, b)
}
```

---

## 3. Дженерик структуры

Поля могут иметь тип, параметризованный дженериком:

```rust
struct Point<T> {
    x: T,
    y: T,
}

let p_int = Point { x: 1, y: 2 };
let p_float = Point { x: 1.0, y: 2.0 };
```

Разные координаты — два параметра: `struct Point<T, U> { x: T, y: U }`.

---

## 4. Дженерик enum

Стандартные `Option<T>` и `Result<T, E>` — примеры дженерик enum:

```rust
enum Option<T> {
    Some(T),
    None,
}

enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

---

## 5. Дженерик методы в impl

Блок `impl` может быть параметризован типом структуры и дополнительно своими типами:

```rust
impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}

impl Point<f64> {
    fn distance_from_origin(&self) -> f64 {
        (self.x * self.x + self.y * self.y).sqrt()
    }
}
```

Первый — метод для любого `Point<T>`. Второй — только для `Point<f64>`.

---

## 6. Trait bounds (ограничения типов)

Чтобы внутри обобщённого кода вызывать методы или операции, тип должен реализовывать нужные трейты:

- `T: PartialOrd` — сравнение (`<`, `>`).
- `T: Copy` или `T: Clone` — копирование/клонирование.
- Несколько: `T: PartialOrd + Copy`.

### Синтаксис where

Для сложных сигнатур удобнее вынести ограничения в блок `where`:

```rust
fn complex<T, U>(t: T, u: U) -> T
where
    T: Clone + PartialOrd,
    U: Debug,
{
    // ...
}
```

Читаемость выше, чем в строке: `fn complex<T: Clone + PartialOrd, U: Debug>(...)`.

---

## 7. Типичные ошибки

- Забыть trait bound: компилятор выдаст ошибку «no implementation for T for trait X».
- Путать параметры типов: один параметр `T` для обоих полей — оба одного типа; два параметра — могут быть разными.

---

## 8. Best practices

- Минимально необходимые bounds: только те трейты, которые реально используются.
- Для длинных списков bounds использовать `where`.
- Именовать параметры типов кратко, но понятно: `T`, `U`, `E` для ошибок — общепринято.

---

## 9. Итоги

- Дженерики: параметры типа в `<>` для функций, структур, enum, impl.
- Trait bounds ограничивают типы и позволяют вызывать методы (`T: PartialOrd`, `T: Copy` и т.д.).
- `where` упрощает чтение сложных сигнатур.
- Код мономорфизируется при компиляции — нулевая стоимость абстракции.

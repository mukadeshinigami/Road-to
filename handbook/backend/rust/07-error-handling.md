# Блок 7: Обработка ошибок (Error Handling)

## Цель

Научиться **правильно обрабатывать ошибки** в Rust: когда паниковать, когда возвращать `Result`, как использовать `?`, как вводить свои типы ошибок и следовать best practices.

---

## 1. Два вида ошибок: паника и Result

В Rust принято разделять:

- **Восстанавливаемые ошибки** — вызывающий код может решить, что делать (например, «файл не найден»). Для них используется **`Result<T, E>`**.
- **Невосстанавливаемые ошибки** — баги, нарушение инвариантов. Обычно **`panic!`** (или паника из `unwrap`/`expect` в неподходящем месте).

В библиотечном коде предпочтительно возвращать `Result` и не вызывать панику, если только это не явно документировано.

---

## 2. panic!

Макрос `panic!("message")` завершает программу с сообщением и backtrace (если настроено).

```rust
panic!("something went wrong");
```

Использовать при:
- программистских ошибках (assert-like);
- в тестах (`assert_eq!` при неудаче вызывает панику);
- в бинарнике, когда дальнейшая работа невозможна и это ожидаемо (например, не найден обязательный конфиг).

Не использовать для обычной бизнес-логики (неверный ввод, отсутствие файла и т.п.) — лучше `Result`.

---

## 3. Result<T, E> — углублённо

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

### Обработка через match

```rust
use std::fs::File;

let f = File::open("hello.txt");
match f {
    Ok(file) => { /* use file */ }
    Err(e) => eprintln!("Could not open file: {:?}", e),
}
```

### unwrap и expect

- `unwrap()` — вернуть значение при `Ok`, при `Err` — паника.
- `expect("msg")` — то же, но с кастомным сообщением паники.

Имеют смысл в прототипах или когда ошибка по смыслу невосстановима. В библиотеках и продакшене чаще используют `?` или явный `match`.

---

## 4. Оператор ? для проброса ошибок

В функции, возвращающей `Result`, можно «пробросить» ошибку наверх одной буквой `?`:

```rust
use std::fs::File;
use std::io::Read;

fn read_username_from_file() -> Result<String, std::io::Error> {
    let mut f = File::open("hello.txt")?;
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}
```

Если `File::open` или `read_to_string` вернут `Err`, функция сразу вернёт этот `Err`. Иначе работа продолжается.

`?` можно использовать для типов, реализующих трейт `From` для преобразования ошибок (см. ниже). В `main` с Rust 2018+ можно возвращать `Result<(), E>` и использовать `?` внутри.

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let _ = File::open("missing.txt")?;
    Ok(())
}
```

---

## 5. Собственные типы ошибок

Часто вводят enum или структуру для ошибок приложения:

```rust
#[derive(Debug)]
enum AppError {
    Io(std::io::Error),
    Parse(String),
}

impl From<std::io::Error> for AppError {
    fn from(e: std::io::Error) -> Self {
        AppError::Io(e)
    }
}
```

Тогда `?` автоматически конвертирует `std::io::Error` в `AppError::Io` благодаря `From`. Возвращаемый тип функции: `Result<T, AppError>`.

---

## 6. Box<dyn Error>

Тип-трайт-объект для «любой ошибки»:

```rust
use std::error::Error;

fn do_something() -> Result<(), Box<dyn Error>> {
    let _ = std::fs::read_to_string("file.txt")?;
    Ok(())
}
```

Удобно в приложениях, когда не хочется описывать свой enum ошибок. В библиотеках чаще используют конкретный тип ошибки.

---

## 7. match vs if let vs ?

- **match** — когда нужно обработать оба варианта или несколько типов ошибок по-разному.
- **if let** — когда интересует только один вариант (например, только `Err`).
- **?** — когда ошибку нужно передать вызывающему коду.

---

## 8. Best practices

- В библиотеках: возвращать `Result` с конкретным типом ошибки, реализовать `std::fmt::Display` и `std::error::Error`.
- В приложениях: можно использовать `Box<dyn Error>` или свой enum с `From` для конвертации.
- Не злоупотреблять `unwrap()`/`expect()` — только там, где паника допустима.
- Документировать, какие функции могут паниковать.

---

## 9. Итоги

- Восстанавливаемые ошибки — `Result<T, E>`; невосстановимые — `panic!`.
- Обработка: `match`, `if let`, `unwrap`/`expect` (осторожно), `?` для проброса.
- Свои ошибки: enum/struct + при необходимости `From` и `impl Error`.
- `Box<dyn Error>` — универсальный тип ошибки в приложениях.

# Блок 12: Практика — Умные указатели (Smart Pointers)

## Цель практики

Закрепить Box, Rc, RefCell и при необходимости Arc/Mutex на простых структурах данных.

## Задание 1: Связный список через Box

### Описание

Односвязный список: узел содержит значение и `Option<Box<Node>>` — ссылку на следующий узел. Реализовать добавление в конец и вывод списка.

### Требования

- `struct Node { value: i32, next: Option<Box<Node>> }`
- Функция `append(head: &mut Option<Box<Node>>, value: i32)` или метод.
- Функция вывода: обход по next и печать value.

### Вопросы

1. Почему следующий узел — именно `Option<Box<Node>>`, а не просто `Box<Node>`?
2. Где хранятся узлы — на стеке или в куче?

### Пример каркаса

```rust
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

fn append(head: &mut Option<Box<Node>>, value: i32) {
    let mut current = head;
    while let Some(ref mut node) = current {
        current = &mut node.next;
    }
    *current = Some(Box::new(Node { value, next: None }));
}
```

Реализуйте вывод и проверьте в main.

## Задание 2: Дерево с несколькими владельцами (Rc)

### Описание

Простое дерево: у узла есть значение и список дочерних узлов `Vec<Rc<Node>>`. Создать корень и несколько детей, обойти и вывести значения (например, рекурсивно).

### Требования

- `struct Node { value: i32, children: Vec<Rc<Node>> }`
- Создать корень и добавить в него детей через `Rc::clone`.
- Функция `print_tree(node: &Rc<Node>, indent: u32)` — рекурсивный обход с отступом.

### Вопросы

1. Зачем здесь Rc, а не Box?
2. Что произойдёт, если сделать цикл (ребёнок ссылается на предка)?

Реализуйте и выведите небольшое дерево.

## Задание 3: Граф через Rc и RefCell

### Описание

Узлы графа с исходящими рёбрами: каждый узел хранит список соседей `Vec<Rc<RefCell<Node>>>`. Добавить два узла, связать их друг с другом (двунаправленное ребро), вывести соседей.

### Требования

- `struct Node { id: u32, neighbors: Vec<Rc<RefCell<Node>>> }`
- Создать два узла, добавить друг друга в neighbors через `RefCell::borrow_mut()`.
- Зачем RefCell: у узла есть неизменяемая ссылка через Rc, но список соседей нужно изменять при добавлении рёбер.

### Подсказка

После создания узлов сохранить `Rc::clone` на оба, затем в каждом через `borrow_mut()` добавить в neighbors ссылку на другой. Вывести id и количество соседей.

Реализуйте с осторожностью к циклам (здесь два узла — цикл из двух ссылок допустим; счётчик Rc не обнулится при циклических ссылках — в продвинутых задачах используют Weak).

## Задание 4: Разделяемое состояние (Arc<Mutex<T>>)

### Описание

Счётчик, разделяемый между двумя потоками. Каждый поток 10 раз увеличивает счётчик на 1. Использовать `Arc<Mutex<u32>>`; в каждом потоке клонировать Arc, в цикле lock(), увеличить, отпустить guard.

### Требования

- `let counter = Arc::new(Mutex::new(0u32));`
- Два `thread::spawn` с `move || { ... }`, внутри `Arc::clone(&counter)`.
- После join ожидать значение 20.

### Пример

```rust
use std::sync::{Arc, Mutex};
use std::thread;

let counter = Arc::new(Mutex::new(0));
let mut handles = vec![];

for _ in 0..2 {
    let c = Arc::clone(&counter);
    handles.push(thread::spawn(move || {
        for _ in 0..10 {
            *c.lock().unwrap() += 1;
        }
    }));
}

for h in handles {
    h.join().unwrap();
}
println!("{}", *counter.lock().unwrap());
```

Запустите и убедитесь, что итог 20.

---

## Итоги практики

- Box для единственного владельца и рекурсивных структур (список).
- Rc для разделяемого владения в одной нити (дерево с общими узлами).
- Rc<RefCell<T>> для графов с обратными ссылками в одной нити.
- Arc<Mutex<T>> для разделяемого изменяемого состояния между потоками.

## Цель практики

## Задание 1: Макрос для упрощённого создания HashMap

### Описание

Макрос `map!`, который по аналогии с `vec![]` строит `HashMap`: например, `map! { "a" => 1, "b" => 2 }` или `map! { a => 1, b => 2 }`. Результат — выражение типа `HashMap<_, _>`.

### Требования

- Паттерн с повторением пар ключ–значение (например, `$($k:expr => $v:expr),*`).
- В расширении: создать HashMap, в цикле вставить пары (использовать повторение).
- Не забыть `use std::collections::HashMap` в макросе или в вызывающем коде.

### Пример

```rust
macro_rules! map {
    ($($k:expr => $v:expr),* $(,)?) => {{
        let mut m = std::collections::HashMap::new();
        $( m.insert($k, $v); )*
        m
    }};
}

fn main() {
    let m = map! { "one" => 1, "two" => 2 };
    println!("{:?}", m);
}
```

Реализуйте и проверьте на разных типах ключей/значений (при необходимости укажите типы или используйте строки/числа).

## Задание 2: Макрос для логирования

### Описание

Макрос `log!(level, "format", args...)`, который в зависимости от уровня (например, "info", "error") выводит в stderr строку с префиксом уровня и временем (опционально). Упрощённый вариант: только формат и аргументы, префикс уровня.

### Требования

- Паттерн: минимум уровень и сообщение; можно `($level:ident, $($arg:tt)*)` и внутри вызвать `eprintln!` с префиксом.
- Пример вызова: `log!(info, "started");` или `log!(error, "failed: {}", e)`.

### Каркас

```rust
macro_rules! log {
    (info, $($arg:tt)*) => {
        eprintln!("[INFO] {}", format!($($arg)*))
    };
    (error, $($arg:tt)*) => {
        eprintln!("[ERROR] {}", format!($($arg)*))
    };
}
```

Добавьте уровень `warn` и проверьте вызовы.

## Задание 3: Упрощение повторяющегося кода

### Описание

Есть несколько структур с одним полем и методом `get`: `struct A(i32); impl A { fn get(&self) -> i32 { self.0 } }`. Написать макрос `single_field!(Name, Type)`, который генерирует структуру-обёртку и метод `get`.

### Требования

- Макрос принимает имя типа и тип поля (например, `single_field!(Meters, f64)`).
- Генерирует `struct Meters(f64); impl Meters { pub fn get(&self) -> f64 { self.0 } }` (и при необходимости конструктор).

### Пример

```rust
macro_rules! single_field {
    ($name:ident, $t:ty) => {
        struct $name($t);
        impl $name {
            pub fn get(&self) -> $t {
                self.0
            }
        }
    };
}

single_field!(Meters, f64);
fn main() {
    let m = Meters(3.5);
    println!("{}", m.get());
}
```

Реализуйте и создайте 2–3 таких типа.

## Задание 4: Derive-макрос (опционально)

### Описание

Если готовы к процедурным макросам: отдельный крейт с `proc-macro = true`, зависимостями `syn` и `quote`. Простой derive, например `#[derive(Hello)]`, который генерирует функцию `hello() -> String` с именем типа. Иначе — пропустить или описать шаги (создание крейта, объявление proc-macro, парсинг атрибута, генерация impl).

### Требования (кратко)

- Новый крейт, в Cargo.toml: `[lib] proc-macro = true`, зависимости syn, quote.
- Функция с сигнатурой `fn hello_derive(input: TokenStream) -> TokenStream`.
- Парсинг `syn::parse_macro_input!(input as DeriveInput)`, извлечение имени типа, генерация `impl Hello for TypeName { fn hello() -> String { "TypeName" } }` через `quote::quote!`.
- В основном проекте зависимость на этот крейт и `#[derive(Hello)]` на тестовой структуре.

Это задание можно оставить на потом и ограничиться декларативными макросами.

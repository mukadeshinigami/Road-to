# Блок 16: Макросы (Macros)

## Цель

Понять **метапрограммирование** в Rust: декларативные макросы (macro_rules!), паттерны и повторения, гигиена, введение в процедурные макросы (derive, attribute, function-like).

---

## 1. Зачем макросы

Макросы генерируют код на этапе компиляции. От функций отличаются тем, что работают с синтаксисом (токенами/деревьями), могут иметь переменное число аргументов и повторять фрагменты кода. Использование: сокращение дублирования, DSL, генерация boilerplate (например, derive).

---

## 2. Декларативные макросы: macro_rules!

Объявление: `macro_rules! name { (pattern) => { expansion }; ... }`. Вызов: `name!(...)` с синтаксисом, подходящим под один из паттернов.

```rust
macro_rules! say_hello {
    () => {
        println!("Hello!");
    };
}

say_hello!();
```

---

## 3. Паттерны: фрагменты (fragment specifiers)

В паттерне переменные захватываются с указанием типа фрагмента:

- **expr** — выражение.
- **ident** — идентификатор.
- **ty** — тип.
- **block** — блок `{ ... }`.
- **stmt** — утверждение.
- **pat** — паттерн.
- **tt** — одно токенное дерево (token tree); часто для «остатка».
- **item**, **meta**, **lifetime**, **literal** — и др.

Пример:

```rust
macro_rules! my_macro {
    ($x:expr) => { $x * 2 };
    ($($y:expr),*) => { ... };
}
```

---

## 4. Повторения

Синтаксис: `$( ... ) sep *` или `+` (ноль или больше / один или больше). Разделитель `sep` — например, запятая. В расширении тот же синтаксис: `$( element )*`, при этом `element` может использовать захваченную переменную.

```rust
macro_rules! vec_str {
    ($($e:expr),*) => {
        {
            let mut v = Vec::new();
            $( v.push($e.to_string()); )*
            v
        }
    };
}
```

---

## 5. Гигиена (hygiene)

Макросы в Rust гигиеничны: имена, введённые внутри макроса, не «утекают» наружу и не конфликтуют с именами в месте вызова (на уровне идентификаторов). Исключения — метки циклов и некоторые другие конструкции. Это снижает риск случайных захватов переменных.

---

## 6. Процедурные макросы (введение)

Процедурные макросы — это крейты, которые принимают входной поток токенов и возвращают новый поток. Пишутся на Rust в отдельном крейте с `proc-macro = true` в Cargo.toml. Три вида:

- **Derive макросы** — `#[derive(MyTrait)]` на структуре/enum; генерируют реализацию трейта.
- **Attribute-like** — `#[my_attr(args)]` на элементе; могут менять элемент или генерировать новый код.
- **Function-like** — выглядят как вызов функции `my_macro!(...)`; на входе и выходе — токены.

Для процедурных макросов нужны крейты вроде `syn` (парсинг) и `quote` (генерация кода). Подробности — в The Book и специализированных гайдах.

---

## 7. Типичные ошибки

- Несовпадение числа повторений в паттерне и в расширении — макрос может не скомпилироваться или вести себя неожиданно.
- Использование переменной макроса вне блока повторения, где она не определена.
- Слишком общий паттерн (например, только `$($t:tt)*`), перехватывающий больше, чем нужно — порядок правил важен, более специфичные должны быть раньше.

---

## 8. Best practices

- Декларативные макросы — для повторяющегося кода с понятными правилами; не усложнять без нужды.
- Документировать ожидаемый синтаксис вызова и примеры.
- Процедурные макросы — при необходимости сложной генерации или интеграции с атрибутами/derive; учитывать время компиляции.

---

## 9. Итоги

- Декларативные макросы: macro_rules!, паттерны с fragment specifiers (expr, ident, tt и т.д.), повторения $( )*.
- Гигиена уменьшает конфликты имён.
- Процедурные макросы: derive, attribute-like, function-like; пишутся в отдельном крейте.

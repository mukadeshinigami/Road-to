# Блок 23: Практика — Unsafe Rust

## Цель практики

Минимальное использование unsafe: обёртка над C (или имитация), разыменование сырых указателей, понимание контракта безопасности.

---

## Задание 1: Обёртка над C-функцией (или имитация)

### Описание

Объявить внешнюю функцию (например, из libc: `extern "C" { fn abs(n: i32) -> i32; }`) и вызвать её из safe-обёртки: `pub fn safe_abs(n: i32) -> i32 { unsafe { abs(n) } }`. Если libc недоступен — описать шаги: создание статической библиотеки на C, компиляция, link в build.rs, объявление extern и вызов.

### Требования

- Минимальный объём unsafe (только вызов в одном месте).
- Документировать, почему вызов считается безопасным (контракт C-функции).

Реализуйте обёртку и unit-тест (safe_abs(-5) == 5).

---

## Задание 2: Разыменование сырых указателей

### Описание

Создать массив на стеке, получить сырой указатель на первый элемент, в unsafe-блоке разыменовать и прочитать значение. Показать, что указатель валиден в момент разыменования (область видимости переменной охватывает unsafe-блок).

### Требования

- let arr = [1i32, 2, 3]; let p: *const i32 = arr.as_ptr(); unsafe { *p }.
- Кратко объяснить в комментарии: почему это безопасно (указатель не null, выровнен, время жизни arr).

Реализуйте и выведите значение.

---

## Задание 3: Низкоуровневая структура (опционально)

### Описание

Реализовать простой «буфер» с сырым указателем: выделение через alloc (или Box::new и сырой указатель из Box), запись байта по индексу в unsafe, освобождение при drop. Обёртка должна гарантировать: доступ только в границах длины, один владелец, освобождение один раз.

### Требования

- Структура с полем *mut u8 (или *const u8) и len; метод write_at(index, byte) — unsafe внутри или с проверкой границ снаружи.
- impl Drop для освобождения (если использовали alloc; иначе Box и не освобождать вручную).

Задание можно упростить до «обёртки над Vec с одним unsafe-методом по необходимости».

---

## Задание 4: Документирование инвариантов

### Описание

Для любой своей unsafe-функции или блока написать короткий комментарий (или doc), перечисляющий инварианты, которые обязан соблюдать вызывающий (или которые гарантирует сама функция). Пример: «Указатель p должен быть валиден, выровнен и указывать на массив длины не менее n».

Реализуйте один такой комментарий к своему коду из заданий 1–3.
